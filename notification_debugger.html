Dispatch a manual FCM message to trigger a remote notification banner on your physical phone or tablet using Firebase REST API.

1 Retrieve FCM Registration Token
Run your Flutter app in debug mode on your phone or simulator. Once loaded, search the terminal console logs for the string:

🔥 NEW FCM DEVICE TOKEN: <token>

Copy this token and paste it into the Device Registration Token field in the sidebar of this page.
2 Extract Auth Token (JWT)
Log in to the web panel on Chrome or Safari.
  • Right-click and choose Inspect.
  • Go to the Application (or Storage) tab.
  • Under Local Storage, look for key: token.
  • Copy the value and paste it into the Bearer Auth Token field in the sidebar.
3 Check WebSocket (Socket.io) Real-time Data
Fill in your Socket URL (e.g. https://api.dev.batman.co.in) and token. Click Connect Socket.io.
When a status or tower is modified, verify that you see the raw Socket.IO JSON log print in the Unified Logs tab immediately.
4 Verify Website Trigger Banners (Duplicate Test)
While the mobile app is in the **foreground** and connected:
  • Modify a tower status or document from the website admin panel.
  • Expected Behavior on Phone: You should receive exactly **one** push notification banner. The duplicate Socket.IO banner is successfully ignored on Android/iOS/macOS.
  • Expected Behavior on Dashboard: The debugger dashboard should show the raw JSON WebSocket packet received, verifying that the server did broadcast the Socket event.
5 Verify Navigation Routes (FCM Test)
To verify that the phone routes clicks to the correct module views (e.g. Legal or Permissions):
  1. Go to the Trigger Test Push (FCM) tab.
  2. Fill in your Firebase Server Key and select your target Module type (e.g., Legal or Permission).
  3. Click Send Test Push to Device.
  4. When the banner appears on the device, tap it. The app should open and immediately push to the correct screen (e.g., routing to the Legal/Permission module view and highlighting the reference ID).
